# 部署说明（零基础版）

> 适用对象：完全没有计算机基础的操作人员。
> 目标：在 21.63 服务器上把「输电线路智能诊断全息指挥室」跑起来。
> 全程只需要「复制命令 → 粘贴 → 回车」。遇到任何报错，先看文末「遇到问题怎么办」。

---

## 第 0 步：先确认 3 件事（不做任何操作，只确认）

1. 你能登录 21.63 服务器（有账号密码，一般是 root）。
2. 服务器上已经启动了诊断相关服务（数据平台和 5 个 MCP 诊断服务，端口 8000~8005）。—— 这通常是别人已经部署好的，不确定就问运维。
3. 你手上有安装包文件：**`pld-command-center-20260818.tar.gz`**（约 21MB 的一个压缩文件）。

---

## 第 1 步：把安装包拷贝到服务器

你只需要拷贝**这一个压缩包文件**，不需要拷贝整个文件夹。

- 文件位置：你电脑（Mac）上的 `dist-packages` 文件夹里，文件名是 `pld-command-center-20260818.tar.gz`。
- 用你习惯的方式（U 盘、文件传输工具等）把它放到 21.63 服务器的**根目录 `/`** 下。

> 如果你已经把整个目录拷过去了也没关系，在服务器上找到这个 `.tar.gz` 文件即可，下面的步骤一样。

---

## 第 2 步：登录服务器

在你的电脑上打开「终端」（Windows 可用 PuTTY / Xshell，Mac 自带「终端」App），输入：

```bash
ssh root@服务器IP
```

> 把「服务器IP」换成 21.63 服务器的完整 IP 地址（例如 `10.10.21.63`，具体问运维）。
> 第一次连接会问 `Are you sure you want to continue connecting?`，输入 `yes` 回车。
> 然后输入密码。**注意：输入密码时屏幕不会有任何显示，这是正常的**，输完直接回车。

看到命令行前面变成类似 `[root@xxx ~]#` 的样子，就说明登录成功了。

---

## 第 3 步：解压安装包

依次输入下面两条命令（每输入一条按一次回车）：

```bash
cd /
tar xzf pld-command-center-20260818.tar.gz
```

> 第二条命令执行时屏幕没有任何输出、安静几秒后回到命令行，这是**正常**的，表示解压成功。

解压后输入：

```bash
cd /pld-command-center
ls
```

应该能看到这些东西：

```
README.md  backend  config.env  frontend  install.sh  pld  start.sh  status.sh  stop.sh  wheels
```

看到它们就说明文件都在了。

---

## 第 4 步：一键安装（约 1~2 分钟）

输入：

```bash
./install.sh
```

**正常情况下**你会看到屏幕依次显示：

```
== 1/4 检查 Python 3.10 ==
  使用 /usr/bin/python3.10 (Python 3.10.x)
== 2/4 创建虚拟环境并离线安装依赖 ==
  ...
== 3/4 初始化运行目录 ==
== 4/4 校验安装完整性 ==
  ✓ 依赖完整、关键模块均可正常导入

安装完成。后续步骤：
  ...
```

看到「安装完成」四个字就说明成功了，直接跳到第 5 步。

> 最后一步「校验安装完整性」会真实检查每个依赖是否完好。即使安装过程中断过（断电等），只要最后看到「安装完成」，环境就是完整的，不存在「显示装完其实没装完」的情况。

**如果屏幕上出现「错误」或「✗」**，不要慌，翻到文末「遇到问题怎么办」找对应的错误。

---

## 第 5 步：一键启动

输入：

```bash
./start.sh
```

你会看到类似这样的输出：

```
== 外部服务连通性检查（MCP/数据平台，需同机已启动）==
  ✓ 127.0.0.1:8000 可达
  ✓ 127.0.0.1:8001 可达
  ✓ 127.0.0.1:8002 可达
  ✓ 127.0.0.1:8003 可达
  ✓ 127.0.0.1:8004 可达
  ✓ 127.0.0.1:8005 可达
== 1/2 PLD 诊断平台 (6000) ==
  启动 pld (pid xxxxx) → logs/pld.log
== 2/2 本项目后端+前端 (8100) ==
  启动 backend (pid xxxxx) → logs/backend.log

启动完成。浏览器入口：http://<服务器IP>:8100
```

- 如果 8000~8005 全部显示绿色的 **✓ 可达**：完美，继续下一步。
- 如果某个端口显示黄色的 **! 不可达**：先记下来是几号端口（这只影响对应那个诊断工具，系统照样能打开），然后联系运维确认对应服务是否启动。

---

## 第 6 步：打开网页验证

在**你自己电脑的浏览器**里输入地址：

```
http://服务器IP:8100
```

> 把「服务器IP」换成 21.63 服务器的完整 IP，例如 `http://10.10.21.63:8100`。

能看到 3D 指挥室页面，就说明**部署成功了**。

> 如果网页打不开，最常见的原因是服务器防火墙没放行 8100 端口，翻到文末「遇到问题怎么办」第 4 条。

---

## 日常使用（记住这 3 条命令就够了）

所有命令都要先 `cd /pld-command-center` 再执行：

| 你想做什么 | 输入的命令 |
|---|---|
| 看服务是不是在运行 | `./status.sh` |
| 停止服务 | `./stop.sh` |
| 重新启动（改了配置后用） | `./stop.sh` 然后 `./start.sh` |

`./status.sh` 显示的样子：

```
服务           端口     状态
pld            6000     运行中 (pid xxxxx)
backend        8100     运行中 (pid xxxxx)
---- 外部服务（应已运行）----
外部服务        8000     可达
...
```

> 注意：`stop.sh` 只会停掉本系统的两个服务（6000 和 8100），**不会**碰 8000~8005 的外部诊断服务，放心使用。

---

## 遇到问题怎么办

### 1. `./install.sh` 报错：「未找到 python3.10」或「版本为 Python 3.x，要求 Python 3.10」

服务器上没有安装 Python 3.10。这步需要运维协助安装，把这句话原样转给运维即可：

> 「请在这台服务器上安装 Python 3.10（Ubuntu/Debian 还需 `apt install python3.10-venv`；CentOS/Rocky 需 `yum install python310`）。」

装好后重新执行 `./install.sh`。

### 2. `./install.sh` 报错：「创建虚拟环境失败」

执行下面命令安装 venv 组件后重试：

Ubuntu/Debian 系统：
```bash
apt update && apt install -y python3.10-venv
```

CentOS/Rocky 系统：
```bash
yum install -y python310
```

然后重新 `./install.sh`。

### 2.5 `./install.sh` 最后一步显示「✗ 校验未通过」

说明有依赖包没装完整（比如上次安装被中途打断）。执行以下命令彻底重建环境：

```bash
rm -rf venvs
./install.sh
```

这条命令会删掉旧环境从头安装，整个过程约 1~2 分钟，安全可靠。

### 2.6 安装中途断网/断电/终端被关闭

直接重新执行 `./install.sh` 即可，它会自动接着装。如果重跑后校验步骤仍报「✗」，按上面 2.5 条重建环境。

### 2.7 历史关联里点开 Word/WPS 文件，提示「暂不支持在线预览」

安装包已**内置 LibreOffice 便携版**（解压即用，无需 root），正常情况下 Word/WPS 点开即可在弹窗内查看转换后的 PDF。若仍出现该提示，说明便携版在这台服务器上未能运行（极少数最小化系统缺基础库），请联系运维安装系统版 LibreOffice：

```bash
# Ubuntu/Debian：apt install -y libreoffice-writer
# CentOS/Rocky/麒麟：yum install -y libreoffice-writer

cd /pld-command-center && ./stop.sh && ./start.sh
```

> 若转换出的 PDF 里中文显示为方块，说明服务器缺中文字体，联系运维安装中文字体包（如 `fonts-noto-cjk` / `wqy-microhei-fonts`）后重启服务即可。

### 3. `./start.sh` 提示「端口 xxxx 被占用」

说明有旧程序还占着端口。输入：

```bash
./stop.sh
./start.sh
```

即可（stop 会自动清理残留进程）。

### 4. 服务都显示「运行中」，但浏览器打不开 `http://服务器IP:8100`

大概率是防火墙。在服务器上执行：

```bash
firewall-cmd --permanent --add-port=8100/tcp && firewall-cmd --reload
```

> 如果提示 `firewall-cmd: command not found`，说明防火墙不是 firewalld，请运维放行 8100 端口即可。

### 5. 页面能打开，但发起诊断后所有工具都失败

输入 `./status.sh`，看下半部分「外部服务」里 8000~8005 哪个显示**不可达**，联系运维检查对应服务。

### 6. 想看更详细的错误信息

两个日志文件记录了所有细节：

```bash
tail -50 /pld-command-center/logs/backend.log
tail -50 /pld-command-center/logs/pld.log
```

把屏幕上的内容截图发给技术人员即可。

## 附：这个系统由什么组成（了解即可，不用操作）

| 端口 | 是什么 | 谁负责启动 |
|---|---|---|
| 8100 | 指挥室网页 + 后端（你的浏览器入口） | 本安装包 |
| 6000 | PLD 诊断平台（诊断引擎） | 本安装包 |
| 8000 | 数据平台 | 服务器上已有，不用管 |
| 8001~8005 | 5 个诊断服务（雷电/覆冰/风偏/鸟害/微气象） | 服务器上已有，不用管 |

本系统对诊断服务的依赖全部通过 `localhost`（本机）访问，**只要它们都跑在这台 21.63 服务器上就能用，不需要任何额外配置**。
