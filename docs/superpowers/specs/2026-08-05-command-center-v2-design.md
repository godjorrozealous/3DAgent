**状态：** 已获用户逐节批准

## 背景与根因记录

本次测试暴露的缺陷与已查证根因：

1. **「无法调整」**：复盘快捷按钮把「调整权重为 2」等文本经 `sendChat` 转发 PLD，带会话前缀的消息被意图分类器误判为新诊断，创建新会话并劫持活跃会话，后续权重调整落入无诊断结果的新会话 → 返回「无法调整」。（已于 2026-08-04 修复：快捷按钮改 `echoChat` 仅本地回显）
2. **异议轮空报告**：统一重跑消息「诊断文本 + 【复盘异议】将 Lightning 权重调整为 0.1」被 PLD 意图分类器判为 `adjust_weight` 意图而非诊断意图，PLD 只改权重即 complete（无报告无 summary），后端把它当作有效完成轮 → 弹出「复盘报告内容为空」。日志证据：`logs/diagnosis/2026-08-05/sess_defe4e03_100048858.json`（events 仅 thinking+complete，report_len=0）。
3. **摘要缩略/比对错乱**：与 2 同源——空完成轮的 summary 覆盖了有效数据，右侧摘要缩略、报告面板、replay_compare 三处数据不同源。

已核实的 PLD 平台事实（方案 A 成立依据）：

- `adjust_weight`/`exclude` 意图命令把权重/排除真实写入会话 action_log 与状态
- `recheck` 命令先清除该工具 `tool_outputs_cache` 再重新执行（`recheck.py:49-50`），但不把新输出写回缓存
- 诊断重跑（MODIFYING 状态）不清缓存：无异议工具命中缓存直接复用、不调用 MCP；被重查工具缓存已清 → 重新执行
- PLD 有 `DELETE /api/skills/<name>` 端点

## 1. 复盘主循环 v2

```
复盘开始 → 整轮诊断 → 逐项确认
   ↓
收集本轮全部确认决策
   ├─ 存在异议 → 司令统一提报：
   │    ① 结构化异议（权重/排除/重查/时间段）逐条单独发 PLD
   │       （单一意图不会误判；recheck 清缓存并重跑该工具）
   │    ② 自由文本/新数据异议 拼入【复盘异议，本次诊断必须采纳】后缀
   │    ③ 发「裸诊断消息（+后缀）」触发整轮重诊断
   │       → 无异议工具命中缓存复用，不再调用 MCP
   │    ④ 重跑结果再次逐项确认，回到 ↑
   └─ 全部无异议 → 才允许进入报告审核
        ├─ 报告表述问题 → 仅改报告 → 再问
        ├─ 诊断流程问题 → 回到整轮重跑
        └─ 满意 → _finish_run
```

最多 5 轮防止死循环。

**空完成守卫**：重跑流的 `complete` 若不带报告/summary（PLD 误判意图的兜底），后端不当作有效诊断轮：记日志告警、保持上一轮报告与摘要、不进入报告审核，事件流提示用户通过报告审核的「诊断流程问题」重提。

**摘要/比对一致性**：`report_summary` 与 `replay_compare` 只使用有效完成轮的 summary；右侧摘要缩略、报告面板、比对面板三处同源（`last_summaries.replay`）。

**新数据展示**
- 对话提交的新数据按 `override` 类异议记录 `value_overrides[tool]`
- 重跑后确认事件携带 `override` 字段，结构化结果区顶部显示「已改值：…」（复用现有展示位）

## 5. 错误处理

- 结构化异议命令下发失败：记日志，该条异议拼入【复盘异议】后缀兜底下发，不中断
- 重跑空完成：见第 1 节守卫
- 重跑流异常：沿用 `confirm_queue_clear` 复位 + 卡死会话自动复位重试
- 策略删除失败：该条标记失败其余继续，刷新列表并提示
- 报告审核 1800s 超时：维持按满意结束

## 7. 缺陷修复追加（2026-08-06）

复测暴露的两个缺陷、根因与修复方案（均已落地）：

### 7.1 复盘权重异议不得固化到 PLD 会话

**现象**：复盘中将 Lightning 权重调为 0.1，复盘结束后该修改仍留在 PLD 会话 `active_weights` 中，影响后续所有诊断。

**根因**：PLD `AdjustWeightCommand`（`adjust_weight.py:46`）调用 `session_manager.update_weights` 把权重**持久化到长生命周期会话**（按 line_name 复用）。异议统一重跑 v1/v2 只下发调整命令，从未还原——权重修改本只应随「保存策略 + 激活」生效。

**修复**（backend commit `0e9831f`，`agent_manager.py`）：
- 复盘开局快照会话 `active_weights`
- 本轮有 weight 类异议时，在 `finally` 中（排队下一线路**之前**）按快照逐工具下发恢复命令；快照缺失时回退 `strategy_builder.DEFAULT_WEIGHTS`
- 恢复后广播日志「已将本轮调整的权重恢复为调整前数值」+ 刷新 `session_snapshot`（HUD 立即回到调整前）
- 持久化路径不变：只有「保存策略 → 激活」能真正改会话权重

测试：`backend/tests/test_weight_restore.py`（重跑生效 + 结束后还原 + 无权重异议不下发恢复命令）。

### 7.2 面板摘要与报告结论不一致 → 摘要改由 LLM 结论块产出

**现象**：报告正文结论为「风偏放电，加权置信度 0.360」，右侧面板摘要却显示「雷击-绕击 0.98」。

**根因**：报告与摘要是两条产出路径——报告正文由 LLM 按 skill 规则加权计算后撰写；而 `summary` 由代码 `_extract_summary()`（`report_composer.py:236`）对工具原始置信度做 **argmax（不做加权）** 得出。两者结论天然可能背离（0.360 = 0.45×0.8 风偏加权 vs 0.985 雷击原始）。

**关键设计决策（用户裁定）**：摘要不得用任何代码硬编码加权逻辑——「它应该就是报告正文的摘要，两者共用 LLM 的产出逻辑；如果硬编码，将来策略里用户把权重去掉了怎么办」。加权规则本就定义在 skill 中，代码重算会在 skill 变更时失真。

**修复**（vendor PLD commit `9d4033c`，`report_composer.py`）：
- prompt 格式要求新增第 6 条：报告末尾输出 ```` ```conclusion ```` JSON 块 `{"fault_type", "confidence"(0-1), "primary_tool"}`，须与「诊断结论」章节最终结论一致
- `compose()` 新增 `_split_conclusion()`：解析该块作为 `summary`，并从报告文本中剥离；置信度 >1 按百分数归一化（÷100），保留 3 位小数
- 块缺失或解析失败：告警并回退原 `_extract_summary` argmax 逻辑（策略去掉权重等场景不崩）

测试：`vendor/diagnosis-agent/tests/unit/test_report_composer.py::TestConclusionBlock`（结论块优先/百分数归一化/缺失回退/非法 JSON 回退/prompt 含要求）。
